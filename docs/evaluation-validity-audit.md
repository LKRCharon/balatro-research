# 首轮正式验证：独立有效性审计

审计日期：2026-10-05。范围：`experiments/formal_eval.py`、`protocol.py`、`headless/environment.py`、策略公开观察与私有引擎上下文接口。本文是代码审计，不是全机制认证或最终成绩单。

## 能支持什么结论

本轮对象是冻结的脚本策略，运行在隔离、静音的原游戏参考引擎上。不是 GPT 对局，不是完整纯 Python/Lua 重写，也不是未改装游戏进程。16 个预先分配的 validation 种子只能提供一个小样本验证结果；不能据此认定稳定金注连胜、人类级水平或卡牌设计失衡。

主要指标应是 `wins / all assigned jobs`。同时分别列出 win、loss、error、未完成数和真实终局数。技术错误计入分母，不应被描述成引擎正常判负。Wilson 区间描述本轮成功比例的不确定性，不覆盖引擎偏差、策略选型偏差或未来分布变化。

## 已核验的保护

- 注册表把种子按整局分到 train / validation / test；动作样本不是独立随机拆分单位。
- 正式准备流程要求选中的 validation 未被分配过任务；已见人工局进入 train。
- claim、reset、record 三个阶段核对分区和任务；测试分区不能由开发环境 reset 消费。
- 注册策略保存源码和上下文哈希，运行前和正常记分时复核；不可覆盖已完成任务。
- 环境剔除 seed / RNG / draw_order 字段，并删除抽牌堆逐牌身份；背面牌被替换为隐藏占位。
- 整副自有牌的匿名多重集合与可见弃牌用于信念状态，不传递抽牌顺序。假想抽牌使用独立 Python RNG。
- 每个变更先落盘 intent，再记录 result；未决变更阻止盲目重试。引擎端口使用进程锁。
- 连胜按事先登记的 seed_id 顺序计算，不使用有利的并发完成顺序。

## 完成结果审计

全部 16 个分配任务已有结论：**0 胜、14 个真实 GAME_OVER 负局、2 个技术错误**，共 1,201 个已完成游戏动作。成功率为 0/16，Wilson 95% 区间为 [0, 19.36%]；固定登记顺序最长连胜为 0。应称为“16 个任务全部结案”，不能称为“16 局均打到自然终局”。

独立脚本 `experiments/audit_formal_result.py` 在本地完整轨迹上通过：

- 每个分配任务恰有一次 start，种子承诺与预登记一致，未重打失败种子。
- 实际开局均为 BLUE / GOLD；14 个非错误结果均具有真实终局证据。
- 成功动作意图/结果成对、动作数/决策数与结果汇总一致；错误局允许保留未决 intent。
- 公开观察不含 seed、RNG 或 draw_order 字段；动态目标均属于策略可见已知小丑。
- 任务 ID、seed_id、policy_id、逐局结果、总计和连胜顺序相互一致。
- 注册表只读取分区聚合统计确认 test campaign / job 数均为 0，未读取测试种子值。

技术错误分别是 seed_id 151 的 Mercury 和 seed_id 157 的 Jupiter 使用请求被引擎拒绝。它们是接口返回的真实错误，但本审计不将根因武断归为错误策略：临时状态锁、事件就绪性或目标合法性仍待单独复现。两次失败不重试；停下的 worker 剩余未开始任务由相同冻结策略和通过校验的新隔离实例接续。这符合“错误停止 worker”的规则，不改变失败任务结果，恢复事实须随报告披露。

## 解释与后续使用

任何查看后用于调整策略的 validation 结果都已成为开发依据，不能再作为 untouched final test。最终 test 继续封存；仅在候选策略和评估协议均冻结后启用。

正式批量验证可以在首败后继续收集剩余任务，但其“最长连胜”是固定顺序中的描述性统计，并非宣称一次遇败即止的独立纪录尝试。公开报告应同时给出完整序列，避免选择性展示成功段。

卡牌强弱需要控制出现机会、购入价格、底注、经济、组合与存活选择偏差。简单的“买过该牌的局胜率”不能解释为牌的因果效果；本轮首先验证数据管线与候选策略，尚不足以给所有卡牌贴上平衡好坏标签。
