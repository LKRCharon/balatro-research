## 冻结与调度

协议与候选代码在开始执行前推送于 `6b8c3e1`。候选文件的 SHA-256 与 Git blob 逐项一致；`.gitattributes` 禁止换行转换。策略选择为事先固定的 tail_weight=0.3 基线，不是假装从尚未完成的训练批次挑出的优胜者。

在任何种子执行前，首次准备的协议因增加实际引擎指纹、可见性检查和可公开参数快照而撤回；旧记录保留为 withdrawn_before_execution，最终仍使用同一批 16 个种子 ID，没有根据胜负更换名单。

每局都有唯一一次 start，种子承诺与事前协议一致；策略不接收 seed、RNG 或未来抽牌顺序。使用静音、隔离身份的原引擎与 CLI，尚不是完整脱离游戏渲染架构的规则重写。源码指纹验证也不等同于引擎二进制认证。

## 两个技术错误

- ID 151：第 3 底注，完成 53 个动作后，在 SHOP 使用 Mercury 被引擎拒绝；前一动作是开包选牌。
- ID 157：第 2 底注，完成 35 个动作后，在 SHOP 使用 Jupiter 被引擎拒绝；前一动作是 cash_out。

原局和未决 intent 保留，没有重发动作、重置或补打一遍覆盖失败。按协议停止对应 worker 后，原计划中从未开始的 ID 155/159 由相同代码与引擎指纹的新实例执行，见 [恢复记录 155](scheduler-recovery-155.json) / [159](scheduler-recovery-159.json)。这属于调度恢复，不是人工选择游戏动作。

错误原因尚未确认。原规则允许在商店使用星球牌，但控制器锁、STOP_USE 等临时条件会阻止使用；接口可能在动画逻辑/状态收尾前返回。下一轮应先复现“结算/开包 → 商店立即使用星球”的就绪问题，不能简单把两次拒绝都归因于差策略，也不能静默重试。

## 下一轮优先事项

1. **动作就绪性**：优先解决上述使用星球牌拒绝，增加可见的合法动作/就绪状态，保留不可确定结果，不以自动重发掩盖接口缺陷。
2. **初期即时战力**：ID 144 第一商店花 $5 买 8 Ball，第二商店花 $4 买 Hallucination。第二商店有 $3 的 Jupiter，离店时仍有 $5 却未购买。首 Boss 两手同花各得 260，最终 564/600 失败。这支持建立“近期过关缺口与星球边际收益”的反事实案例，不证明买 Jupiter 必然整局获胜。
3. **Boss 与路线约束**：失败包含 The Mouth、The Psychic、The Arm、The Hook 等，应按具体约束检查合法牌型、弃牌规划和阵容适应，不只最大化当前单手分。
4. **经济投资门槛**：ID 149 早期 $7 现金花 $6 买 Satellite 后仅余 $1，最终在首 Boss 失败。先验证即时战力是否足够，再购买发展牌；尚不能因此认定 Satellite 卡牌设计差。

下一轮改动先在训练种子及上述已看过的诊断案例上开发，再用新验证样本选择候选。最终测试仍是 0 个 campaign / 0 个 job，保持封存。当前结果不支持全卡平衡或趣味性的定量结论。
